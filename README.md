# مرصد — محلل كمي للعملات الرقمية

واجهة عربية RTL ثابتة لتحليل ملفات OHLCV المنشورة داخل مجلد `data/` في مستودع GitHub. لا تحتاج API سوقًا ولا Backend. يحمّل الموقع الكتالوج الصغير أولًا، ثم يقرأ **ملف الزوج والفريم المختار فقط** من نفس الموقع.

> ملفات البيانات المرفوعة إلى هذا المستودع **عامة** لأن المستودع public. لا ترفع بيانات خاصة أو أسرارًا.

## أين أرفع البيانات؟

لكل أصل مجلد، ولكل إطار ملف CSV:

```text
data/
├── catalog.json
├── BTCUSDT/
│   ├── 1d.csv
│   └── 4h.csv
└── ETHUSDT/
    └── 1d.csv
```

1. أنشئ الملف في المسار `data/<SYMBOL>/<TIMEFRAME>.csv`؛ مثال: `data/BTCUSDT/1d.csv`.
2. أضف سجلًا له في `data/catalog.json` داخل مصفوفة `datasets`:

   ```json
   {
     "version": 1,
     "datasets": [
       { "symbol": "BTCUSDT", "timeframe": "1d", "file": "BTCUSDT/1d.csv" }
     ]
   }
   ```

3. ارفع الملف والكتالوج إلى الفرع `main`. يتطلب كل سوق/فريم جديد **الملف وسجل الكتالوج معًا**؛ GitHub Pages لا يتيح للصفحة الثابتة استعراض محتويات المجلد تلقائيًا.

`file` في الكتالوج نسبي إلى `data/`، ولا تكتب `data/` قبله ولا تبدأه بشرطة `/`. سجّل كل زوج/فريم مرة واحدة.

## صيغة CSV

CSV يكفي؛ لا حاجة إلى JSON أو إلى إضافة أعمدة للزوج والفريم. الموقع يستنتجهما من المسار والكتالوج. الأفضل استعمال هذه الترويسة والترتيب:

```csv
timestamp,open,high,low,close,volume
2024-01-01T00:00:00Z,42000,43000,41500,42500,123.45
2024-01-02T00:00:00Z,42500,43200,42100,42800,98.7
```

القواعد:

- يقبل الوقت ISO-8601 أو Unix بالثواني أو بالميلي ثانية.
- يجب أن تكون الشموع مرتبة تصاعديًا من الأقدم إلى الأحدث، مع وقت واحد لكل شمعة؛ الترتيب العكسي أو التكرار يوقف تحميل الملف برسالة واضحة.
- الأرقام عشرية بالنقطة وبدون فواصل آلاف. `Volume` لا يكون سالبًا، و`High`/`Low` يجب أن يحيطا بـ`Open` و`Close`.
- يدعم كذلك تصدير Binance الشائع: ترويسة `open_time,open,high,low,close,volume`، أو صيغة بلا ترويسة يكون أول ستة أعمدة فيها بالترتيب نفسه.
- الصفوف غير الصالحة تُستبعد ويظهر عددها في تنبيه.
- إطار الشمعة (`1m`, `1h`, `4h`, `1d`...) يُكتب في اسم الملف والكتالوج؛ لا يستنتجه الموقع من داخل البيانات.

## الشارت

صفحة الشارت منفصلة عن الملخص، وتستخدم **TradingView Lightweight Charts 5.2.1** من نسخة standalone مضمّنة داخل `vendor/`؛ لا يجلب الموقع المكتبة من CDN ولا يرسل CSV إلى TradingView. عند اختيار زوج وفريم، يحمّل ملفهما من المستودع ويعرض كامل سجل الشموع افتراضيًا، مع الحجم في لوحة مستقلة.

يستطيع المستخدم سحب الشارت وتحريكه، وتكبيره بعجلة الفأرة أو بإصبعين على الهاتف، وضبط محوري الزمن والسعر بالسحب، وتغيير الرسم بين الشموع وخط الإغلاق، وإظهار/إخفاء EMA 20 وEMA 50 وFVG وOrder Block والعلامات. أزرار «كل الشموع» و«أقدم/الأحدث» وأزرار التكبير تكمل أدوات المكتبة. اختصارات لوحة المفاتيح: `+`، `-`، `Home`، والأسهم.

هذه **Lightweight Charts** وليست منصة TradingView الكاملة؛ توفر تفاعل الشارت والطبقات الموجودة هنا، وليست مجموعة أدوات الرسم اليدوي أو خدمات TradingView السحابية. يتضمن المشروع ترخيص Apache-2.0 وإشعار الإسناد المطلوب في `vendor/`، كما يظهر رابط TradingView وإشعارها أسفل الشارت.

كلما كبر الملف زاد استهلاك ذاكرة المتصفح؛ رسم مئات آلاف الشموع دفعة واحدة قد يكون بطيئًا على هاتف محدود الذاكرة. حجم الملف الذي يمكن استعراضه عمليًا يعتمد على الجهاز.

## تشغيل وفحص

- **محليًا / Acode:** انسخ المجلد كاملًا وشغّل معاينة Acode المحلية أو خادمًا ثابتًا؛ وحدات JavaScript و`fetch` تحتاج `http://localhost` عادةً بدل فتح `file://` مباشرة.
- **الحاسوب:** `python3 -m http.server 8000` ثم افتح `http://localhost:8000`.
- **GitHub Pages:** يمكن تشغيل ملفات المشروع الثابتة دون Python أو خادم تطبيق. تفعيل Pages ونشره خطوة منفصلة من تعديلات الملفات.

لفحص CSV يدويًا قبل رفعه (اختياري):

```bash
python3 tools/validate_ohlcv.py data/BTCUSDT/1d.csv
```

## ما الذي يحسبه؟

- **الاتجاه:** EMA 20 مقارنة بـEMA 50 وميل EMA 20؛ يحتاج 50 إغلاقًا.
- **RSI:** الفترة 14 بطريقة Wilder؛ التشبع الشرائي عند ≥70 والبيعي عند ≤30.
- **القمم/القيعان:** Pivot بخمس شمعات على كل جانب. النقطة تتأكد بعد خمس شموع لاحقة ولا تمثل معرفة لحظية.
- **FVG:** فجوة من ثلاث شمعات؛ تُحذف من المناطق المفتوحة بعد عبور حدها المقابل كاملًا.
- **Order Block:** آخر شمعة معاكسة قبل إزاحة تكسر Pivot ونطاقًا قريبًا، وتُبطل بعد إغلاق يتجاوزها.
- **الحجم السنوي:** أعلى شمعة حجمًا لكل سنة وتغير السعر بعد 20 شمعة متاحة؛ لا يُخلط حجم العملة بقيمتها الدولارية.
- **تنصيف Bitcoin:** التواريخ التاريخية ترتبط بارتفاع كتلة معروف؛ الموعد التالي عند 1,050,000 متوقع حول 2028، لكن يومه غير ثابت مسبقًا.

التحليل وصفي وليس توصية أو إشارة تداول. يعتمد على جودة البيانات وتوقيتها.
